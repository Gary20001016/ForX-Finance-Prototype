# 内容审核先于多语言的统一流程设计

## 1. 目标

所有会产生新消息内容的入口统一改成“先审核默认语言内容，再进行多语言生产与语言审核”：

- 人工消息模板
- 事件消息模板
- 人工任务中的临时消息

避免源内容最终被内容审核驳回时，已经产生无效的机器翻译成本和语言审核工作。

使用已发布模板创建的人工任务不重新生产多语言；任务仍需审核受众、渠道、时间、有效期等任务配置。事件通知规则不产生新内容，继续独立审核规则配置。

## 2. 统一流程

```text
编辑默认语言内容与目标语言
→ 提交内容审核
├─ 驳回：返回创建人修改，重新提交内容审核
└─ 通过：锁定默认语言内容
         → 需要多语言或默认语言需专项审核
            → 创建外部机翻/原文审核任务
            → 按语言人工审核
            → 全部语言通过
         → 不需要语言审核
            → 直接完成语言门禁
         → 模板自动发布 / 临时消息自动进入待发送或发送中
```

内容审核通过后不再进行第二次业务审核。语言审核只负责目标语言准确性、变量完整性和 Markdown 结构，不重新审核受众与任务配置。

## 3. 审核对象

### 3.1 人工消息模板

```text
草稿
→ 内容审核中
→ 内容已通过
→ 多语言生产/语言审核
→ 已发布
```

- 创建模板时可选择默认语言、目标语言、渠道、展示位置和风险等级。
- 提交后先在审核中心生成“人工消息模板”内容审核工单。
- 内容审核通过后才允许创建外部翻译任务。
- 所有目标语言通过后模板自动发布。
- 单语言且该语言不要求专项审核时，内容审核通过后直接发布。

### 3.2 事件消息模板

流程与人工消息模板一致。

- 系统事件、所有者团队和事件字段变量在内容审核前确定。
- 内容审核通过后才创建翻译任务。
- 多语言全部通过后自动发布，供事件通知规则选择。
- 已发布模板继续保持不可编辑。

### 3.3 临时消息

临时消息提交内容审核时冻结当前任务快照：

- 默认语言内容
- 目标语言
- 正式渠道
- 前台一级分类与二级主题
- 风险等级
- 受众与排除条件
- 发送方式、计划时间和任务时区
- 消息有效期

审核结果：

- 驳回：任务进入“待修改”，创建人修改后重新提交。
- 通过且无需语言审核：立即发送任务进入“发送中”，定时任务进入“待发送”。
- 通过且需要语言审核：自动创建翻译或原文审核批次；全部语言通过后，立即发送任务进入“发送中”，定时任务进入“待发送”。

如果多语言完成时计划发送时间已经到达，但消息仍在有效期内，任务立即进入“发送中”；如果消息有效期已经结束，任务进入“已过期”，不再发送。

### 3.4 使用已发布模板的人工任务

- 模板已经完成内容与多语言审核，不重复审核模板内容。
- 任务审核仍检查受众、渠道、计划时间、有效期、风险和频控。
- 任务审核通过后直接进入“待发送”或“发送中”。

### 3.5 事件通知规则

- 继续使用已发布的事件消息模板。
- 只审核事件条件、风险升级、变量映射、去重、重试和渠道配置。
- 不创建新的多语言任务。

## 4. 状态设计

### 4.1 对外主状态

模板列表继续只展示四个主状态：

```text
草稿 / 审核中 / 驳回 / 已发布
```

不增加大量并列状态。

### 4.2 当前节点

使用独立的“当前节点”表达内部进度：

```text
编辑内容
内容待审核
内容已驳回
创建翻译任务
翻译返回待审核
语言审核中
发布就绪
已发布
```

任务继续使用既有任务生命周期状态，并增加当前节点：

```text
任务配置审核
多语言生产
语言审核
发送就绪
```

### 4.3 前端数据字段

模板和临时消息内容快照增加：

```text
contentApprovalStatus
contentApprovalId
contentApprovedAt
contentApprovedBy
contentApprovedHash
workflowStage
translationBatchId
translationReadiness
```

`contentApprovedHash` 由默认语言、所选渠道内容、变量、分类、主题和风险生成，用于判断内容审核结果是否仍对应当前源内容。

## 5. 编辑与失效规则

- 内容审核中，提交快照只读；创建人可以撤回审核。
- 内容被驳回后允许修改，原审核工单结束。
- 内容审核通过后，默认语言源内容锁定。
- 修改目标语言审核稿不会使源内容审核失效。
- 在发布或发送前，如果创建人撤回并修改默认语言内容，则：
  - 内容审核结果失效；
  - 已创建的翻译批次失效；
  - 所有目标语言审核结果失效；
  - 对象返回草稿或待修改；
  - 必须重新提交内容审核。
- 已发布模板仍不可编辑，需要复制后创建新模板。

## 6. 页面交互

### 6.1 模板编辑器

- 保留默认语言、目标语言和渠道配置。
- 首个主操作改为“保存并提交内容审核”。
- 内容审核通过前不显示可操作的“创建外部机翻任务”按钮。
- 内容通过后自动创建翻译批次，无需创建人再次点击。
- 多语言全部通过后自动发布，并展示只读模板详情。

### 6.2 多语言进度

- 内容审核未通过：显示“等待内容审核”，不展示虚假的翻译进度。
- 内容审核通过且翻译创建中：显示“正在创建翻译任务”。
- 翻译有结果：直接展示各语言译文、审核人和操作入口。
- 全部语言通过：显示“多语言已通过，已自动发布/已进入发送流程”。

### 6.3 审核中心

新增或调整内容审核工单：

- 人工消息模板
- 事件消息模板
- 临时消息任务

审核详情展示冻结的默认语言内容、渠道预览、展示位置、风险、变量和任务配置。审核通过时由统一后续动作决定是创建多语言批次、自动发布还是进入发送流程。

### 6.4 列表

模板列表显示：

```text
主状态
当前节点
内容审核结果
多语言进度
```

任务列表继续显示任务状态，同时在详情和多语言进度中展示当前节点，不将翻译状态混入任务主状态。

## 7. Lark通知

消息发送到“消息审核群”：

```text
提交内容审核 → @内容审核人
内容被驳回 → @创建人
内容审核通过并创建翻译 → 不单独要求创建人操作
翻译返回待审核 → @对应语言审核人
全部语言通过 → @创建人，说明已自动发布或进入发送流程
无法创建翻译/无可用审核人 → @创建人和相关管理员
```

内容审核与多语言审核不发送到“消息异常群”；只有系统执行失败才进入异常群并 @创建人和运维。

## 8. 模拟数据

模拟数据至少覆盖：

- 人工模板：内容待审核
- 人工模板：内容驳回
- 事件模板：内容通过、翻译创建中
- 事件模板：翻译返回待审核
- 模板：全部语言通过并已发布
- 临时消息：任务内容待审核
- 临时消息：内容通过、语言审核中
- 临时消息：语言全部通过、待发送
- 单语言普通内容：内容通过后直接发布
- 单语言专项语言：内容通过后进入原文审核

不得保留“多语言已通过但内容尚未提交审核”的旧模拟状态。

## 9. 异常处理

- 没有可用内容审核人：不创建审核工单，对象保持草稿并提示配置权限。
- 内容审核重复提交：返回当前有效工单，不重复创建。
- 内容审核通过动作重复执行：复用同一内容哈希对应的翻译批次。
- 外部翻译失败：内容审核结果继续有效，允许重试翻译。
- 没有可用语言审核人：保留翻译结果并阻断发布或发送。
- 内容哈希与审核快照不一致：禁止创建翻译和发布，返回草稿重新审核。
- 审核工单被撤回或失效：后续完成回调不得推进对象状态。

## 10. 验收标准

- 所有新内容必须先通过内容审核才能创建多语言任务。
- 人工模板、事件模板和临时消息使用同一先后规则。
- 内容审核驳回时不会产生新的翻译任务。
- 内容审核通过后自动进入需要的语言流程。
- 多语言全部通过后不再要求二次内容审核。
- 模板自动发布，临时消息自动进入待发送或发送中。
- 使用已发布模板的任务和事件通知规则保持原有独立审核职责。
- 修改源内容会使内容审核和翻译结果全部失效。
- 页面主状态保持简洁，当前节点能够准确解释流程进度。
- 模拟数据不存在违反新顺序的状态组合。
