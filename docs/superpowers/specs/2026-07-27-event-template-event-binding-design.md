# 事件消息模板绑定事件目录设计

## 目标

事件消息模板必须从事件目录选择一个系统事件，并以该事件作为模板字段、展示位置与可用变量的唯一来源。模板创建后不得更换绑定事件。

本次只调整事件消息模板及其在事件通知规则中的选择方式，不改变人工消息模板。

## 核心规则

1. 新建事件消息模板时必须选择系统事件。
2. 系统事件选项来自事件目录，不在模板模块内维护第二份事件数据。
3. 选择事件后自动带出并锁定：
   - 事件名称与事件编码
   - 前台一级分类
   - 前台二级主题
   - 风险等级
   - 可用消息变量
4. 模板保存后，绑定事件永久不可更换，包括草稿、审核中、驳回和已发布状态。
5. 所有者团队为事件消息模板必填字段。
6. 事件通知规则选择模板时，只展示绑定当前事件且已发布的事件消息模板。
7. 模板正文仍由操作者编辑，系统不根据事件自动生成正文。

## 数据模型

`MessageTemplate` 增加：

```ts
eventId?: string;
```

约束：

- `usageScope === "event"` 时，`eventId` 必填。
- `usageScope !== "event"` 时，不使用 `eventId`。
- 更新事件模板时忽略传入的新 `eventId`，始终保留原绑定值。
- `owner` 对事件模板必填。

事件目录中的 `SystemEventDefinition` 继续提供：

```ts
id
name
defaultCategory
defaultTopic
defaultRisk
variables
```

模板不复制一份可编辑的事件变量配置；页面根据 `eventId` 从事件目录解析。

## 新建与编辑页面

事件模板编辑器顶部字段顺序：

1. 系统事件
2. 模板名称
3. 所有者团队
4. 适用场景
5. 前台一级分类
6. 前台二级主题
7. 风险等级
8. 默认语言

新建时：

- “系统事件”为必选下拉框，展示“事件名称 · 事件编码”。
- 未选择事件前，不提供事件变量。
- 选择事件后写入 `eventId`，自动设置分类、主题和风险。
- 分类、主题、风险以只读方式展示。
- Markdown 与 Push 正文变量选择器只显示当前事件允许的变量。

编辑时：

- “系统事件”显示原绑定事件并禁用。
- 分类、主题、风险继续只读。
- 所有者团队可按现有模板编辑权限修改。

## 列表与详情

事件模板列表增加：

- 系统事件：事件名称与事件编码
- 所有者团队

事件模板详情增加：

- 系统事件
- 事件编码
- 所有者团队

人工模板列表与详情不增加这些字段。

## 事件通知规则

创建或编辑事件通知规则时：

1. 操作者先选择系统事件。
2. 消息模板下拉框只展示满足以下条件的模板：
   - `usageScope === "event"`
   - `status === "已发布"`
   - `template.eventId === selectedEventId`
3. 切换事件时清空已选择模板，防止事件与模板失配。
4. 保存规则时再次校验模板绑定事件是否与规则事件一致。

## 现有数据迁移

现有事件模板按模板编码补齐绑定事件：

| 模板编码 | 系统事件 |
|---|---|
| `deposit_credited` | `deposit.credited` |
| `withdraw_success` | `withdrawal.succeeded` |
| `order_filled` | `order.filled` |
| `liquidation_warning` | `liquidation.warning` |

无法识别的历史事件模板不得静默绑定错误事件；标记为未绑定，仅允许查看，完成数据修复后才能继续使用。

现有事件模板补齐所有者团队：

- 已有 `owner` 时保留。
- 缺失时根据事件调用方对应业务团队补齐。
- 无法识别时使用“消息运营”作为迁移兜底值。

## 异常处理

- 未选择系统事件：阻止保存并提示“请选择系统事件”。
- 未选择所有者团队：阻止保存并提示“请选择所有者团队”。
- 事件目录中找不到已绑定事件：模板只读，并显示“绑定事件已不存在”。
- 模板使用了当前事件不允许的变量：草稿可保存并提示；提交审核时阻止。
- 规则选择的模板与事件不一致：阻止保存并提示重新选择模板。

## 验收标准

1. 新建事件模板必须从事件目录选择事件。
2. 事件选择后，展示位置和风险自动带出且不可编辑。
3. 编辑已有事件模板时不能更换事件。
4. 变量选择器只展示当前事件允许的变量。
5. 所有者团队在事件模板编辑器、列表和详情中可见。
6. 人工消息模板不受影响。
7. 事件通知规则只显示当前事件对应的已发布模板。
8. 切换规则事件会清空原模板选择。
9. 历史四个事件模板能正确迁移到对应事件。
