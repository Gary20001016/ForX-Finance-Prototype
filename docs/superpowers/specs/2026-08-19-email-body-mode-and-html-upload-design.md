# ForX Finance 邮件正文模式与 HTML 多语言上传设计

## 1. 目标

调整消息中心邮件模板的正文架构，使同一邮件模板在编辑时只选择一种正文模式：纯文本正文或 HTML 文件。纯文本正文由外部机器翻译任务生成多语言版本；HTML 正文由运营按语言直接上传完成稿，不再进入机器翻译和多语言翻译审核。

本设计适用于人工消息模板、临时消息和事件消息模板中的邮件渠道，并覆盖模板编辑、内容审核、多语言生产、预览、测试发送和发布门禁。

本设计覆盖 `2026-08-19-email-channel-integration-design.md` 中与邮件正文结构、多语言及预览相关的规则；其他 Email 渠道、投递、统计和供应商规则保持不变。

## 2. 已确定方案

采用“正文模式互斥、标题与预览文字独立”的结构：

- 邮件标题 `subject` 和预览文字 `preheader` 始终独立于正文模式。
- 正文模式 `bodyMode` 只能是 `text` 或 `html`。
- `text` 模式维护一份源语言纯文本正文，并通过外部机翻任务生成目标语言正文。
- `html` 模式不维护待翻译的源 HTML；运营为每个启用语言（含源语言）分别上传已经完成本地化的完整 HTML 文件。
- 一个模板版本不能同时把纯文本正文和 HTML 正文作为正式发送内容。
- 切换正文模式后，只有当前模式参与校验、审核、预览、测试发送、内容哈希和发布。

不采用“同时维护 HTML 与纯文本并设置发送优先级”，因为会形成两套可能不一致的正式内容；不采用富文本编辑器生成 HTML，因为本次需求明确要求上传 HTML 文件。

## 3. 页面与交互

### 3.1 邮件编辑区

邮件编辑区按以下顺序展示：

1. 邮件类型、发件身份等非语言配置。
2. 源语言邮件标题。
3. 源语言预览文字。
4. 正文类型切换：`纯文本`、`HTML 文件`。
5. 当前正文模式的编辑区。
6. 多语言完成情况、预览和测试发送。

### 3.2 纯文本模式

- 展示源语言纯文本编辑器。
- 操作者选择目标语言后提交外部机翻任务。
- 每个目标语言展示机器译文、人工修订稿和审核状态。
- 邮件预览展示对应语言的标题、预览文字与纯文本正文。
- 正式发送使用 `text/plain` 内容。

### 3.3 HTML 文件模式

- 不展示富文本编辑器或源 HTML 输入框。
- 按已选择语言展示上传槽位；源语言和每个目标语言各有一个槽位，每个语言最多一份生效 HTML 文件。
- 每个语言卡片展示：语言、文件名、文件大小、上传人、上传时间、校验状态、内容审核状态，以及预览、替换、删除操作。
- HTML 文件通过校验后可打开桌面与移动宽度预览。
- HTML 正文不出现在多语言审核待办中，也不显示“机翻中”或“翻译返回待审核”。
- HTML 文件仍进入正常内容审核；内容审核用于确认页面内容、品牌、链接和合规信息，不属于翻译质量审核。
- 正式发送使用上传并净化后的 `text/html` 内容。系统可以从 HTML 提取兼容性纯文本，但该文本仅作为邮件客户端回退，不成为第二套可编辑正文。

### 3.4 正文模式切换

- 草稿状态允许切换正文模式。
- 当前模式已有内容时，切换前弹出确认提示，说明翻译结果、上传文件和已有审核会失效。
- 切换后可以暂存原模式草稿用于恢复，但原模式内容不得参与预览、审核、测试发送和发布。
- 内容审核中或多语言处理中切换模式时，当前审批、翻译批次和已通过语言全部失效，模板回到草稿。
- 已发布模板不能直接切换正文模式，必须创建新版本。

## 4. 多语言流程

### 4.1 公共文本字段

无论正文模式为何，标题和预览文字都遵循同一流程：

```text
源语言标题/预览文字
  → 提交外部机翻任务
  → 返回目标语言结果
  → 人工多语言审核
  → 目标语言标题/预览文字通过
```

变量名、URL 和不可翻译片段在机翻任务中保持原样。

### 4.2 纯文本正文

纯文本正文与标题、预览文字一起进入外部机翻任务，并按语言进行人工多语言审核。一个目标语言只有标题、预览文字和纯文本正文全部通过，才算该语言的邮件翻译通过。

### 4.3 HTML 正文

HTML 正文采用以下流程：

```text
运营按语言上传 HTML 完成稿
  → 文件与安全校验
  → 变量一致性校验
  → 普通内容审核
  → 该语言 HTML 正文可用
```

HTML 正文不调用外部机翻接口，不生成机器译文，不进入多语言审核页面。发布时，系统按语言把源语言原文或已经通过多语言审核的目标语言标题和预览文字，与已经通过内容审核的该语言 HTML 正文组合成最终邮件。

### 4.4 发布门禁

每个必选语言必须同时满足：

- 标题已完成外部机翻并通过多语言人工审核。
- 预览文字为空，或已完成外部机翻并通过多语言人工审核。
- 纯文本模式下，纯文本正文已完成外部机翻并通过多语言人工审核。
- HTML 模式下，该语言 HTML 已上传、校验通过并通过普通内容审核。

任一必选语言未满足条件时不可发布，并在语言列表中显示具体缺项。

## 5. HTML 文件规范

### 5.1 文件要求

- 仅允许上传 `.html` 或 `.htm` 文件。
- 文件必须是可独立渲染的完整 HTML 文档，包含 `doctype`、`html`、`head` 和 `body`。
- 页面布局使用邮件客户端兼容的表格布局和内联 CSS。
- 图片、按钮和跳转链接使用绝对 HTTPS 地址。
- 图片必须包含 `alt` 文本。
- 营销邮件必须包含系统约定的退订变量。
- 文件中的模板变量使用平台统一的 `{{ variable_name }}` 格式。

### 5.2 禁止内容

- `script`、`iframe`、`form`、JavaScript 协议和内联事件处理器。
- 外部 CSS、不可控字体依赖和本地文件路径。
- 未登记变量、密钥、Token 或用户隐私数据。
- 超出平台限制的大文件或大体积 Base64 图片。

### 5.3 校验结果

上传后必须返回结构化结果：

- 文件结构是否完整。
- 危险标签、属性和协议是否存在。
- 图片与链接是否使用允许的地址。
- 当前语言的变量集合是否与模板变量声明一致。
- 各语言 HTML 的变量集合是否一致。
- 营销邮件是否包含退订变量。
- 清理后 HTML 是否可生成桌面与移动预览。

阻断级问题禁止提交审核；警告级问题允许操作者确认后继续。

## 6. 数据模型

邮件内容建议调整为：

```ts
type EmailBodyMode = "text" | "html";

interface EmailMessageContent {
  subject: string;
  preheader: string;
  bodyMode: EmailBodyMode;
  textBody?: string;
  htmlAssets?: Record<string, EmailHtmlAsset>;
}

interface EmailHtmlAsset {
  locale: string;
  fileName: string;
  fileSize: number;
  sourceHtml: string;
  sanitizedHtml: string;
  generatedText: string;
  sha256: string;
  uploadedBy: string;
  uploadedAt: string;
  validationStatus: "pending" | "passed" | "blocked";
  contentReviewStatus: "pending" | "approved" | "rejected";
  validationIssues: EmailHtmlValidationIssue[];
}
```

实现时可以按现有原型的数据结构做兼容映射，但页面和业务判断必须只认 `bodyMode` 对应的正文。

标题、预览文字及纯文本正文继续保存在翻译批次的机器结果、人工稿和通过稿中。HTML 文件不复制到机器翻译结果；翻译批次只保存该语言 HTML 资产引用和可用状态。

## 7. 修改与失效规则

- 修改源语言标题或预览文字：使所有目标语言对应字段的机翻及审核结果失效。
- 修改源语言纯文本正文：仅在纯文本模式下使目标语言正文结果失效。
- 替换某个语言的 HTML：只让该语言 HTML 的校验与内容审核失效，不影响其他语言的 HTML，也不自动使标题和预览文字的翻译审核失效。
- 修改变量声明：重新校验所有语言的 HTML；存在缺失或多余变量时阻止发布。
- 删除必选语言 HTML：该语言立即变为未完成并阻止发布。

## 8. 错误处理

- 外部机翻失败：保留已完成语言，允许按失败语言重试。
- HTML 上传失败：保留原生效文件，只有新文件校验通过并确认替换后才覆盖。
- HTML 校验阻断：展示具体标签、属性、变量或链接问题，不创建审核任务。
- HTML 内容审核驳回：显示驳回原因，替换文件后重新提交该语言审核。
- 最终组合缺少标题、正文或必选语言版本：测试发送和正式发布均被阻止。

## 9. 前端影响范围

- 人工消息模板与事件消息模板的邮件编辑器。
- 临时消息创建页的邮件编辑器。
- 邮件预览组件及测试发送入口。
- 多语言工作区：按正文模式决定是否展示正文翻译字段。
- 多语言审核页：HTML 正文不创建或展示翻译审核项。
- 内容审核详情：HTML 模式按语言展示最终 HTML 预览与校验结果。
- 模板/任务列表：展示正文模式及各语言完成情况。
- 领域类型、示例数据、校验器、内容哈希和发布门禁。
- 模块化 PRD 中的邮件模板、多语言和审批章节。

## 10. 验收标准

1. 邮件正文可以在纯文本与 HTML 文件两种模式中选择，正式内容不能同时使用两种模式。
2. 纯文本模式下，标题、预览文字和正文均通过外部机翻与多语言人工审核。
3. HTML 模式下，标题和预览文字通过外部机翻与多语言人工审核，HTML 正文按语言直接上传且不进入翻译审核。
4. HTML 上传后展示安全、变量和兼容性校验结果，并能按语言预览、替换和删除。
5. HTML 正文必须通过普通内容审核，但页面不得把该状态描述为“多语言审核”。
6. HTML 模式发布时按语言正确组合标题、预览文字和对应 HTML 文件。
7. 缺少必选语言 HTML、标题审核或必要预览文字审核时，系统明确提示缺项并禁止发布。
8. 替换单个语言 HTML 只使该语言的 HTML 内容审核失效。
9. 草稿切换正文模式会确认并重置相关流程；已发布版本不能直接切换。
10. 人工模板、临时消息和事件模板使用同一套邮件正文模式和门禁规则。

## 11. 非目标

- 不在前端实现真实外部机翻或邮件供应商调用。
- 不提供可视化拖拽式邮件设计器。
- 不在平台内翻译或编辑上传 HTML 的可见文本。
- 不允许一个模板版本同时发送手工纯文本正文和 HTML 正文。
- 不改变现有 Email 供应商、发送记录、退信、投诉、退订和数据分析架构。
