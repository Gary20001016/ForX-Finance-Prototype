# 事件通知规则风险升级覆盖设计

## 目标

允许事件通知规则在使用“条件触发”时，根据命中条件将事件消息模板的风险等级向上覆盖。模板风险始终是下限，规则不能降低模板风险。

## 核心规则

- 风险等级顺序为：低 < 中 < 高 < 关键。
- “事件触发”始终继承模板风险，不展示风险覆盖配置。
- “条件触发”可选择“不覆盖”或高于、等于模板风险的等级。
- 切换为事件触发、切换事件或切换模板时，清除无效的风险覆盖值。
- 最终风险取模板风险与规则覆盖风险的较高值。
- 规则列表、规则详情、审核中心和审批流程均使用最终风险。
- 规则详情保留风险来源，明确展示模板风险和条件覆盖风险。
- 模板后续更新风险时，最终风险重新按较高值计算，规则覆盖不能造成降级。

## 数据模型

在 `EventNotificationRule` 增加可选字段：

```ts
riskOverride?: RiskLevel;
```

现有 `risk` 字段继续表示最终生效风险：

```ts
risk = max(template.risk, riskOverride)
```

这样现有列表、筛选、审批和高风险判断可继续读取 `rule.risk`，同时通过 `riskOverride` 保留覆盖来源。

## 规则编辑器

选择事件和同事件的已发布模板后，展示：

```text
模板风险：中
条件风险覆盖：高
最终生效风险：高
```

交互约束：

- 仅条件触发显示“条件风险覆盖”。
- 默认值为“不覆盖，继承模板风险”。
- 可选项过滤掉低于模板风险的等级。
- 选择等于模板风险表示显式确认，不改变最终风险。
- 保存前再次校验，防止通过非 UI 调用写入降级值。

## 数据流

1. 操作者选择系统事件和匹配的已发布事件模板。
2. 模板提供基础风险。
3. 条件触发可选风险覆盖。
4. Store 校验覆盖值不得低于模板风险。
5. Store 写入 `riskOverride` 和计算后的 `risk`。
6. 提交审核时，审批单使用规则最终风险，而不是重新读取模板风险。
7. 高/关键风险继续进入高风险审核要求。

## 兼容与迁移

- 现有规则没有 `riskOverride`，默认继续继承模板风险。
- 读取旧数据时，将 `risk` 规范化为至少不低于当前模板风险。
- 不修改事件消息模板的风险继承逻辑。

## 测试范围

- 条件触发可选择不低于模板风险的覆盖等级。
- 低于模板风险的选项不展示，Store 也拒绝降级覆盖。
- 切换到事件触发后清除覆盖值。
- 创建、编辑规则正确保存覆盖值和最终风险。
- 审核单使用规则最终风险，并按高/关键风险进入对应审核要求。
- 旧规则无覆盖字段时保持原行为。
