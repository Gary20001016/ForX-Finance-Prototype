# 变量测试审核先于多语言的双审设计

## 1. 目标

对所有新建消息内容统一增加变量测试审核门禁：人工消息模板、事件消息模板、临时消息以及事件规则的新内容版本，只要正文或 Push 使用了变量，就必须完成可追溯的变量渲染测试，并与内容审核并行进入审核中心。内容审核和变量审核均通过后，系统才能创建外部机翻任务或原文语言审核任务。

无变量内容维持现有流程：内容审核通过后直接进入需要的多语言流程。使用已发布模板创建人工任务时复用该模板已通过的变量审核结论；任务不覆盖模板内容，因此不重复测试或审核模板变量。

## 2. 统一流程

```text
编辑源内容、渠道与目标语言
  -> 提交前变量语法/白名单校验
  -> 有变量？
     ├─ 否：提交内容审核
     └─ 是：填写或加载测试样例 -> 发送测试并保存测试凭据
              -> 并行创建内容审核 + 变量测试审核
                 ├─ 任一驳回/源快照失效：返回修改；两条审核、测试凭据与翻译结果全部失效
                 └─ 两条均通过且哈希一致：创建外部机翻/原文审核任务
                    -> 全部语言审核通过
                    -> 模板发布 / 临时消息进入待发送或发送中 / 规则内容版本待生效
```

“并行”只表示两张审核工单可同时处理，不表示任一通过即可推进。变量审核人不得审核自己提交的内容；与内容审核使用独立审核任务和结论，默认不分配给同一审核人，若无合格的第二位审核人则明确阻断提交。

## 3. 变量测试与审核证据

### 3.1 提交人测试

含变量内容的提交人必须先完成一次与当前冻结内容一致的测试：

- 手动模板与临时消息：为每个变量填写非空、脱敏的样例值，并向已配置测试账号发送所选渠道的预览。
- 事件消息模板与规则内容版本：从绑定事件的 Schema/测试事件载荷生成变量样例；变量只能来自该事件版本允许的字段，并保留字段到模板变量的映射。
- 每个正式渠道均需有成功的测试结果；站内信分别覆盖 Web 与 App 展示预览，Push 覆盖目标设备预览。
- 测试生成不可变凭据，包含变量清单、出现位置及次数、脱敏样例、各渠道渲染结果、测试账号/事件、执行时间、结果和源快照哈希。

提交源内容、变量、事件绑定/Schema、渠道或内容后，若与测试凭据哈希不一致，测试凭据立即失效，必须重新测试。

### 3.2 变量审核

变量审核详情以已保存的测试凭据为依据，审核人可查看但不能修改源文案或样例；可执行“通过变量审核”或填写原因“驳回变量审核”。审核项包括：变量合法性、样例脱敏、变量映射、变量在各语言/渠道的保留要求、渲染结果、链接/Markdown 结构与风险文案。

## 4. 数据模型与状态机

在模板、临时消息内容与规则内容版本的内容审核状态旁增加以下状态：

| 字段 | 说明 |
|---|---|
| `variable_review_required` | 根据当前源内容提取到的变量决定 |
| `variable_test_status` | `不适用 / 待测试 / 测试通过 / 测试失败 / 已失效` |
| `variable_test_id` / `variable_test_hash` | 测试凭据与它对应的冻结哈希 |
| `variable_review_status` | `不适用 / 待审核 / 已通过 / 已驳回 / 已失效` |
| `variable_review_id` | 独立变量审核工单 ID |
| `variable_reviewed_by` / `variable_reviewed_at` | 审核结论信息 |
| `variable_review_hash` | 审核通过时的测试与内容组合哈希 |
| `variable_review_reason` | 驳回原因 |

审批工单增加 `review_node`（`content` 或 `variable`）、`variable_test_id` 与 `variable_snapshot`。多语言启动条件改为：内容审核状态为“已通过”，并且变量不适用或变量审核状态为“已通过”，且两条通过记录和测试凭据均匹配当前内容哈希。

来源页面的当前节点改为：`编辑内容 → 变量测试（如需要） → 内容审核中 / 变量审核中 → 等待另一项审核 → 创建多语言任务 → 多语言审核中 → 发布/发送就绪`。主状态仍维持模板的“草稿 / 审核中 / 驳回 / 已发布”和任务既有主状态，不混用多语言状态。

## 5. 页面变更

1. 模板编辑器（含事件模板）：增加变量测试卡片、测试样例和已保存凭据；提交按钮根据是否有变量显示“保存并提交内容审核”或“保存、测试并提交双审”。
2. 临时消息创建页：补齐与模板相同的变量测试能力；有变量时不可绕过测试进入提交。
3. 模板列表、任务列表和详情：新增变量测试/审核状态与阻断原因，和内容审核、多语言进度分开显示。
4. 审核中心及抽屉：新增“变量测试审核”类型、筛选、独立指派与通过/驳回操作；详情展示变量测试凭据和渠道预览。
5. 多语言工作区：在双审未同时通过时显示准确等待原因，不创建或展示可操作的外部翻译任务。
6. 事件自动化的规则内容版本：复用事件模板变量测试和双审门禁；测试内容额外展示事件 Schema 和变量映射。

## 6. 编辑、驳回与异常

- 内容审核或变量审核任一驳回，来源对象回到可编辑状态；再次提交必须重新完成变量测试和两项审核。
- 源内容、变量、渠道、目标语言、风险、事件绑定或事件版本变化，会撤回或失效两张待办、变量测试和未完成的翻译批次。
- 无变量内容不创建变量测试或变量审核工单。
- 没有测试账号、测试未覆盖全部渠道、测试失败、没有可用变量审核人或内容/变量双审人不满足职责隔离时，阻断提交并显示可定位原因。
- 外部机翻失败不使两项源语言审核失效；修正源内容后才使它们失效。

## 7. 测试与验收

- 变量存在时，内容审核单独通过不得创建翻译批次；变量审核单独通过也不得创建翻译批次。
- 双审均通过且哈希一致时，只创建一个翻译批次；重复回调保持幂等。
- 无变量内容仅通过内容审核即可进入多语言。
- 模板、临时消息、事件模板与规则内容版本均覆盖变量测试、双审、驳回、编辑失效及多语言推进。
- 审核中心可区分内容审核和变量测试审核，审核详情可以还原变量测试凭据与 Web/App 站内信、App Push 预览。
- 所有源内容变化后，旧测试凭据、两个审核结论和翻译结果均不可继续用于发布或发送。
