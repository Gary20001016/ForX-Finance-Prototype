# Email 全链路演示数据设计

## 目标

在消息中心原型的每个主要业务入口提供至少一条可直接查看的 Email 示例，让操作者无需新建数据即可检查邮件编辑、预览、审核、多语言和投递表现。

## 选定方案

采用“按页面放置代表性案例”的方式，而不是把全部现有记录改成 Email。这样既能覆盖完整链路，也能保留站内信和 App Push 数据用于渠道对比。

## 页面与案例分配

1. 人工消息模板：新增一条已发布的多语言 HTML 营销邮件，包含 `zh-CN` 与 `en-US` 两份 HTML 完成稿。
2. 事件消息模板：为充值到账事件提供一条已发布的纯文本事务邮件，正文含金额、币种和时间变量。
3. 人工消息任务：新增一条引用 HTML 营销模板的待发送任务。
4. 事件消息任务：保留并补全充值到账事件任务，使其拥有可查看的纯文本 Email 内容。
5. 内容审核：新增一条包含 Email 预览的待审核人工消息记录。
6. 多语言审核：新增一条 Email 纯文本翻译记录，标题、预览文字和正文均有源文、机翻及人工稿。
7. 投递明细：确保至少一条 Email 投递记录展示收件人、发送流、打开或退信状态。

## 邮件内容模式

- HTML 示例：标题和预览文字具有多语言审核结果；正文按语言上传 HTML 文件，不进入机翻或多语言审核。
- 纯文本示例：标题、预览文字和正文进入外部机翻与多语言人工审核。

## 数据实现

- 演示记录使用固定 ID，避免刷新后重复创建。
- 新种子数据通过现有状态迁移逻辑合并到浏览器本地数据，不要求用户清空其他演示操作。
- HTML 资源包含文件名、大小、上传时间、校验结果、清洗后预览内容和兼容性纯文本。
- 所有变量必须来自当前模板允许的变量集合。

## 验收标准

- 人工模板、事件模板、人工任务、事件任务、内容审核、多语言审核和投递明细均可找到 Email 示例。
- HTML 示例能切换语言并打开桌面端、移动端预览。
- 纯文本示例能展示翻译前后邮件内容。
- 刷新页面后示例仍存在，且不会重复。
- 全量测试和生产构建通过。
