# 用户消息中心 App / Web HTML 设计

## 目标

提供两个可独立打开的纯 HTML 原型，分别展示 App 和 Web 消息中心。两个页面使用同一套前台分组与后台七类消息映射，但不向普通用户暴露后台分类术语。

## 分类结构

前台一级入口固定为：全部、公告、交易、资产、安全与风控、活动与奖励。

后台分类映射如下：

- 系统公告 → 公告
- 交易通知 → 交易
- 资产通知 → 资产
- 安全通知、风控通知 → 安全与风控
- 活动通知、奖励通知 → 活动与奖励

每个一级入口允许按主题二次筛选。例如公告包含维护升级、新币上线、下架和规则调整；资产包含充值、提现和划转。

价格提醒不并入后台七类消息。它作为用户订阅能力保留独立入口，触发后的提醒记录可通过来源字段接入消息列表。

## App 页面

- 暗色移动端布局，内容宽度适配手机视口。
- 顶部展示标题、未读数、全部已读操作。
- 一级分类横向滚动，二级主题使用紧凑筛选按钮。
- 紧急未读消息置顶并使用醒目的风险区域。
- 点击消息打开底部详情面板，同时标记已读。

## Web 页面

- 桌面端三栏布局：左侧产品导航、中部消息列表、右侧消息概览。
- 一级分类使用左侧列表，二级主题和未读筛选放在列表顶部。
- 点击消息打开右侧详情抽屉。
- 支持全部已读、只看未读以及分类和主题筛选。

## 数据与交互

两个 HTML 文件各自内置同样的演示数据、分类映射和原生 JavaScript，不依赖构建工具、框架、CDN 或外部资源。页面必须能够通过 `file://` 双击打开，也能够被任意静态服务器托管。
