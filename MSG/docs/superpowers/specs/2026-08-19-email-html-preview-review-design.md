# HTML 邮件预览与多语言审核案例设计

## 目标

完善 Email 渠道的基础预览能力，并在多语言审核中心提供一个正文为 HTML 文件的可操作案例。审核人员应能同时判断桌面端、移动端、标题、预览文字、变量和退订链接是否正确，但不能在审核页直接修改 HTML 文件。

## 范围

### HTML 邮件预览

- 同一份 HTML 文件分别以桌面邮件视口和移动邮件视口渲染。
- 演示 HTML 使用响应式邮件写法：流式外层、600px 最大内容宽度、移动端媒体查询、可换行变量和自适应按钮。
- 移动预览必须完整显示标题、正文、金额变量、按钮和页脚，不允许横向裁切。
- 保留邮件标题、发件人、预览文字、邮件类型和正文模式信息。
- 自动提取的纯文本兼容内容改为默认收起的“纯文本兼容内容”，不再作为与桌面、移动并列的第三张预览卡片。
- 纯文本内容只读，由系统从 HTML 自动提取，不作为第二套可编辑正文。

### 多语言 HTML 审核案例

- 在多语言审核中心新增一条指派给当前审核人的日语 HTML 邮件工单。
- 工单渠道显示 Email，正文类型明确显示为 HTML 文件。
- 审核抽屉展示源语言与目标语言的邮件标题、预览文字，以及目标语言 HTML 的桌面和移动预览。
- 展示目标语言 HTML 文件名、语言、校验状态、变量检查和退订链接检查结果。
- 标题与预览文字允许人工修订；HTML 正文只读。
- HTML 正文需要调整时，审核人填写原因并驳回，上传人重新上传对应语言文件后再次提交。
- HTML 文件本身不进入外部机翻；外部任务只处理标题和预览文字。目标语言 HTML 由操作者按语言直接上传。

## 数据设计

- 在现有 Email 演示数据中增加一份 `ja-JP` HTML 资源，包含安全校验通过、内容审核通过和完整变量信息。
- 增加一条独立的待审核翻译批次和审核项，用于展示“标题/预览文字机翻 + 目标语言 HTML 直接上传”的组合流程。
- 审核项复用现有 `sourceChannelContent`、`machineChannelOutput` 和 `humanChannelDraft`；目标语言 HTML 资源随 `humanChannelDraft.email.htmlAssets` 提供。
- 不改变已发布 HTML 模板和现有人工任务的状态，避免演示审核工单影响现有流程案例。

## 组件行为

### EmailPreview

- 桌面和移动 iframe 均使用各自的邮件视口宽度。
- iframe 中的 HTML 仍采用 sandbox 隔离。
- 纯文本兼容内容通过折叠面板展示，默认关闭。

### resolveMultilingualPreview

- HTML 正文模式优先使用审核项中目标语言对应的 `htmlAssets`。
- 审核项未提供目标语言资源时，不错误回退为源语言 HTML；界面显示资源缺失提示并禁止通过。

### TranslationReviewDrawer

- 检测到 Email HTML 模式时，隐藏 Markdown 正文编辑器。
- 使用 Email 预览组件展示目标语言桌面、移动预览和折叠纯文本。
- 保留标题、预览文字修订输入框。
- 展示 HTML 文件元数据和校验结果。
- 审核通过前校验变量完整性、HTML 安全状态和目标语言资源存在性。

## 异常与边界

- 目标语言 HTML 缺失或安全校验失败：显示阻断提示，“专项审核通过”不可用。
- HTML 出现未登记变量或营销邮件缺少退订变量：阻断通过。
- HTML 移动端存在横向溢出：预览必须能直观看出；演示文件自身保证响应式通过。
- 自动提取纯文本为空：显示“未生成兼容性纯文本”，不生成空白大卡片。

## 验收标准

- 人工模板详情中的移动 HTML 预览不再裁切标题、金额变量和按钮。
- 纯文本兼容内容默认收起，可展开查看。
- 多语言审核列表存在一条 Email HTML 正文工单。
- 打开工单后可看到目标语言 HTML 的桌面和移动预览。
- 审核页不能直接编辑 HTML 正文，但可编辑标题和预览文字。
- 缺失或校验失败的目标语言 HTML 无法通过审核。
- 相关组件测试、页面测试、全量测试和生产构建全部通过。
