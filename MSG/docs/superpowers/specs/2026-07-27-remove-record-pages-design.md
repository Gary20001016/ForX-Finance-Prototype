# 移除前端触发记录与发送记录设计

## 目标

后台前端不再提供“触发记录”和“发送记录”两个独立业务页面，降低运营人员理解成本。运行明细只作为后台日志和数据分析的数据来源，不再作为日常操作入口。

## 前端删除范围

- 删除侧边栏中的“触发记录”和“发送记录”。
- 删除 `/triggers`、`/deliveries` 路由及对应页面源码。
- 删除两个页面对应的读写权限配置。
- 删除事件通知规则详情中的“最近触发”模块。
- 删除“查看发送记录”“生成触发记录”等可见入口和文案。

## 保留范围

- 保留 `triggerRecords`、`deliveries` 等底层数据结构和状态方法。
- 保留事件测试、任务发送和投递结果的内部记录能力。
- 保留数据分析对投递数据的聚合使用。
- 后台日志由服务端或数据库保存，不在当前管理端展示。

## 兼容行为

- 删除后的旧地址不再匹配业务路由，进入统一的未找到页面。
- 已保存的旧权限字段在读取时被忽略，不再出现在权限配置页。
- 事件规则详情继续展示规则配置、风险和审核信息，但不展示单次触发明细。

## 验收标准

1. 导航和权限配置中看不到“触发记录”“发送记录”。
2. `/triggers`、`/deliveries` 不再渲染原页面。
3. 事件规则详情中没有“最近触发”。
4. 页面中没有“查看发送记录”操作。
5. 数据分析仍可读取底层投递数据。
